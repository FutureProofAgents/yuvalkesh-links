## השורה התחתונה

סוכן AI שהוא שלכם זה חמש שכבות: מכונה שנשארת דלוקה, gateway שמריץ את הסוכן, מודל, ערוץ שאתם כבר משתמשים בו, וכלים. זיכרון וסקילים מגיעים אחרי שההודעה הראשונה עובדת. כל העניין לקח יום ארוך אחד, ובערך שש שעות מתוכו הלכו על אימות.

השכבות, בסדר שבונים אותן:

1. **מכונה שלא נרדמת.** VPS ב4.95 דולר.
2. **Gateway.** OpenClaw, קוד פתוח, פקודת התקנה אחת.
3. **מודל.** מנוי ChatGPT או Claude שכבר יש לכם, מחובר דרך OAuth. בלי חשבון API חדש.
4. **ערוץ.** טלגרם, כי הוא כבר פתוח אצלכם.
5. **כלים.** Composio, התחברות אחת שפותחת Gmail, יומן, GitHub, Airtable ואת כל השאר.
6. **זיכרון.** קבצי markdown פשוטים שהסוכן קורא בתחילת כל סשן.
7. **סקילים.** חבילות שנבדקו מ־ClawHub.
8. **ניטור.** מקום לראות כל סשן, כל כשל, כל חוק.

## שלב 0: לתת לו מכונה שלא נרדמת

הקיר הראשון שכל בונה פוגש: הסוכן עובד מעולה, ואז סוגרים את הלפטופ והוא מת.

אז הוא לא גר על הלפטופ. הוא גר על VPS של Contabo, הדרגה הזולה ביותר, Ubuntu 24.04, 4.95 דולר בחודש. את ההחלטה בין מקומי, VPS ומנוהל פירקתי במדריך [איך מריצים סוכני AI בענן 24/7](/blog/run-ai-agents-in-the-cloud-24-7). בקיצר: VPS זול על הנייר ועולה לכם בשעות, והמדריך הזה הוא בדיוק השעות האלה, מתועדות כדי שתשרפו פחות מהן.

לשרת מגיעים בפקודה אחת:

```bash

```

כל מה שכתוב מכאן קורה בתוך הסשן הזה. תכתבו את המשפט הזה על פתק. הוא חשוב בהמשך.

## שלב 1: להתקין את ה־gateway

OpenClaw הוא החלק שהופך אפליקציית צ'אט ללוח בקרה של סוכן AI. קוד פתוח ברישיון MIT, נכתב על ידי פיטר שטיינברגר, יצא בנובמבר 2025, החליף שם ארבע פעמים בחודשיים, ועבר לידי OpenClaw Foundation אחרי ששטיינברגר הצטרף ל־OpenAI בפברואר 2026. גרסה 2.0 יצאה ב30 באוגוסט 2026. השרת שלי מריץ 2026.9.2.

התקנה:

```bash
curl -fsSL https://openclaw.ai/install.sh | bash
openclaw onboard
openclaw gateway install
```

אשף ההתקנה מבקש ספק מודל וערוץ. אחר כך ה־gateway רץ כשירות רקע ומגיש דשבורד על פורט 18789, קשור ל־localhost בלבד. הפרט האחרון הוא תכונה, לא באג. את הדשבורד פותחים דרך מנהרת SSH, לעולם לא מהאינטרנט הפתוח.

בור אחד מהשדרוג שלי: אחרי ש־`openclaw doctor --fix` העביר משתני סביבה למקטע חדש בהגדרות, כתובת בסיס ישנה שרדה בקובץ השירות והשתלטה בשקט על ספק המודל. אם הספק מפסיק לענות אחרי שדרוג, בודקים גם את ההגדרות וגם את קובץ השירות ומחפשים שורות סביבה ישנות.

## שלב 2: לחבר מודל בלי חשבון חדש

לא צריך מפתח API כדי להתחיל. OpenClaw יודע להתחבר למנוי ChatGPT הקיים שלכם דרך OAuth:

```bash
openclaw models auth login --provider openai --device-code
```

הפקודה מדפיסה כתובת וקוד. פותחים את הכתובת בטלפון, מקלידים את הקוד, זהו. מנוי Claude עובד באותה צורה דרך ספק Anthropic.

שני בורות:

- תהליך ה־device code צריך טרמינל אמיתי. מעל צינור SSH רגיל הוא נתקע. משתמשים ב־`ssh -tt` או מריצים אינטראקטיבית.
- הקוד פג אחרי 15 דקות. הטלפון ביד לפני שמריצים.

באמצע היום החלפתי את הסשן בטלגרם מ־GPT-5.6 Sol ל־GPT-6 Astra עם `/model` בתוך הצ'אט. ברירת המחדל של המערכת נשארה במקום, רק הסשן הזה השתנה. זו הרזולוציה הנכונה: מתנסים לפי שיחה, שומרים על ברירת מחדל יציבה.

## שלב 3: לתת לו מספר טלפון, כלומר טלגרם

פותחים טלגרם, כותבים ל־@BotFather, מריצים `/newbot`, שומרים את הטוקן. ואז:

```bash
openclaw channels add --channel telegram --token YOUR_BOT_TOKEN
openclaw gateway restart
```

שולחים לבוט הודעה כלשהי, ומאשרים את הצימוד מהשרת:

```bash
openclaw pairing list telegram
openclaw pairing approve telegram CODE
```

אחרי הצימוד הראשון נעלתי את מדיניות ההודעות הפרטיות לרשימת מורשים עם מזהה טלגרם אחד בדיוק: שלי. קודי צימוד פגים אחרי שעה, וזה בסדר. בוט שמדבר עם כל מי שמוצא אותו הוא לא עוזר אישי, הוא חבות.

בנקודה הזאת יש לכם סוכן שעונה בטלגרם. כל מה שאחרי זה הוא להפוך אותו לשימושי.

## שלב 4: לתת לו שם וזיכרון

OpenClaw שומר זיכרון כקבצי markdown בתיקיית העבודה של הסוכן. שלושה חשובים:

- `USER.md` מחזיק מי אתם ואיך אתם אוהבים שמדברים אליכם.
- `MEMORY.md` מחזיק עובדות והחלטות קבועות. הוא נטען בתחילת כל סשן.
- `memory/YYYY-MM-DD.md` מחזיק הערות שוטפות של כל יום.

אם קובץ הזיכרון הקבוע גדל מעבר לתקציב שלו, הקובץ בדיסק נשאר שלם אבל העותק שנכנס לקונטקסט נחתך. שומרים את הקובץ הקבוע קצר ודוחפים פרטים להערות היומיות.

ככה זה נראה בפועל. ב13:55 כתבתי "please be funnier". מאז כל דיווח סטטוס נגמר במשפט אחד. "קלאסי: 1,000 אינטגרציות, מובסות על ידי תיבת טקסט אחת בלתי נראית." הטון גר בזיכרון, לא בפרומפט שהייתי צריך לחזור עליו.

ב16:18 שלחתי הודעה קולית וביקשתי שיתמלל הכל מהתחלה ועד הסוף ושישמור את זה כחוק. הוא כתב את החוק ל־`MEMORY.md` תחת כותרת שקרא לה חוק קבוע לתמלול הודעות קוליות, וכל הודעה קולית מאז מטופלת ככה.

זה כל הטריק עם זיכרון. לא מגדירים את הסוכן. אומרים לו דברים, והוא מתייק.

## שלב 5: לתת לו ידיים, כלומר Composio

סוכן בלי כלים הוא צ'אטבוט. Composio הוא קיצור הדרך: חשבון אחד, התחברות אחת, והסוכן מגיע לאלף אפליקציות דרך OAuth מנוהל.

על השרת:

```bash
openclaw plugins install clawhub:@composio/composio
openclaw plugins enable composio
openclaw config set plugins.entries.composio.hooks.allowConversationAccess true --strict-json
curl -fsSL https://composio.dev/install | sh
composio login --no-skill-install
composio whoami
```

התוסף עצמו דק. הוא קורא ל־CLI המקומי של Composio, אז ההתחברות ב־CLI היא החיבור האמיתי. ברגע ש־`composio whoami` מציג את החשבון שלכם, הסוכן רואה כל אפליקציה שחיברתם בדשבורד של Composio.

השלב הזה לקח לי מ13:16 עד 22:22. תשע שעות. הנה כל סיבה, כדי שאצלכם זה ייקח תשע דקות.

**בור 1: התחברתי על המכונה הלא נכונה.** ה־`composio login` הראשון רץ על הלפטופ שלי. הסוכן גר על השרת. ל־CLI של הסוכן עדיין לא הייתה זהות. הפתק משלב 0 קיים בגלל השעה הזאת.

**בור 2: הקישור נשבר לשתי שורות.** ה־CLI מדפיס את קישור ההתחברות החד פעמי בתוך מסגרת מעוצבת. הטרמינל שלי היה צר, אז התו האחרון של המפתח נפל לשורה הבאה. הקישור שהעתקתי היה קצר בתו אחד, והדשבורד אמר שהקישור לא תקין. הפתרון:

```bash
COLUMNS=200 composio login --no-browser --no-wait --no-skill-install
```

מעתיקים את הקישור השלם לדפדפן ומסיימים עם `composio login --poll --no-skill-install`.

**בור 3: הקישורים פגים מהר, וכל אחד מהם הוא סיסמה.** פעמיים הדבקתי חצי קישור בטלגרם וביקשתי מהבוט "לנקות את הכתובת". הוא סירב לשחזר אותה ואמר שהקישור עכשיו חשוף ושצריך ליצור חדש. הוא צדק. קישור התחברות הוא סיסמה עם טיימר.

**בור 4: הסוג הלא נכון של מפתח.** ל־Composio יש מפתחות משתמש, מפתחות חיבור ומפתחות ציבוריים. רק מפתח המשתמש מאמת את ה־CLI. כשבסוף הדבקתי מפתח, הדבקתי אותו בצ'אט של טלגרם. הסוכן מחק את ההודעה, אמר שלא השתמש במפתח, ואמר לי לבטל אותו וליצור חדש. ואז ביקש שאזין את החדש בשדה מוגן בתוך הדשבורד של OpenClaw, שם הוא לא מופיע בשום לוג.

**בור 5: הדשבורד דורש טוקן.** כדי להגיע לשדה המוגן פותחים את ממשק הבקרה דרך מנהרת SSH:

```bash
ssh -N -L 18789:127.0.0.1:18789 root@YOUR_SERVER_IP
```

בדפדפן פותחים `http://127.0.0.1:18789`, ומדביקים את טוקן ה־gateway מהפקודה `openclaw gateway auth-token --show` בהגדרות החיבור. בלעדיו הדשבורד מציג Offline ו־Unauthorized, וזה בדיוק מה שהוא צריך להציג לזר.

ב22:26 הסוכן פירט את החיבורים שלו: Gmail עם ארבעה חשבונות, Google Docs, Drive, Sheets, Slides, יומן, GitHub, Airtable, Stripe, Vercel, ActiveCampaign ו־Zoom. 12 שירותים, 16 חיבורי חשבון. הסיכום שלו לחוק: "לרובוט יש מפתחות, לא חסינות דיפלומטית." קריאה מותרת. שליחה, מחיקה, פרסום או חיוב עדיין דורשים בקשה מפורשת.

## שלב 6: לתת לו אוזניים, בחינם

ב14:48 ביקשתי הודעות קוליות, וביקשתי לחבר כל שירות תמלול חינמי שיש. הסוכן חיבר אחד. Whisper מקומי, רץ על השרת, עברית כשפת ברירת מחדל, בלי מפתח API, בלי חשבון. הנימוק שלו: כמה מנועים מוסיפים בלבול, לא כוחות על.

התמלול הראשון חזר משובש בחלקו באמצע של הודעה מעורבת בעברית ובאנגלית. במקום לכוונן פרמטרים, שלחתי הודעה קולית אחת: תתמלל הכל מהשנייה הראשונה עד האחרונה, תעבד את כולו לפני שאתה עונה, ותשמור את זה כחוק. הניסיון הבא לקח בערך שתיים וחצי דקות וחילץ את המשמעות המלאה. החוק גר עכשיו בזיכרון.

זה הדפוס של כל היום. כשהפלט חלקי, לא מתקנים את הכלי. כותבים את החוק.

## שלב 7: לתת לו סקילים, אבל לבדוק דרכונים

ClawHub הוא המאגר הציבורי של סקילים ותוספים ל־OpenClaw. סקילים הם נהלים ארוזים שהסוכן מושך לפי הצורך. במעבר אחד הסוכן התקין שבעה: mermaid-diagrams, beautiful-pdf, design, frontend, code-review, systematic-debugging ו־gitx, ואת המנועים שמאחוריהם, Mermaid CLI, Pandoc, WeasyPrint ו־Poppler. אחר כך בדק כל אחד בפועל, יצר SVG אמיתי, PDF אמיתי ועמוד A4, ורק אז דיווח על הצלחה.

הוא גם סירב למשהו. הוא דילג על מועמדים עם אזהרת סיכון בינונית וסירב להתקין "את כל הסקילים מכל האינטרנט". סקילים קהילתיים לא חתומים דיגיטלית. חוקרים של סיסקו מצאו סקיל של צד שלישי שגנב מידע והזריק פרומפטים בלי שהמשתמש ידע. בדיקה היא לא פרנויה, היא המחיר של שוק פתוח.

## שלב 8: לראות אותו עובד, כלומר ניטור

ב18:13 הופיעה שגיאה בטלגרם: "Something went wrong while processing your request." שאלתי מה קרה. האבחון: שינוי אבטחה חיכה חמש דקות לטעינה מחדש, הטעינה נחתה בדיוק כשתשובה נסגרה, והסגירה נכשלה אחרי שהתשובה האמיתית כבר נשלחה. תחרות מרוץ, פעם אחת, התאושש.

ואז שאלתי את השאלה שחשובה: האירוע הזה מופיע בדשבורד שבנית קודם היום? התשובה: לא. הדשבורד היה סיכום שהסוכן עדכן ידנית, לא צינור שקורא את הלוגים.

אז אמרתי: תעשה שהמערכת תעשה את זה. 57 דקות אחר כך היה שירות שאוסף לוגים של ה־gateway בצורה מצטברת, מסווג אירועים לפי חומרה וסיבה, עוקב אחרי מצבים פתוח, התאושש והיסטורי, שומר מונים ל24 שעות ואחוז הצלחה בטלגרם, מסתיר מפתחות וטוקנים לפני כל אחסון, ושומר הכל ב־SQLite מקומי. שש בדיקות אוטומטיות עברו. המרוץ מקודם מופיע עכשיו כשורה: Critical, Recovered.

ב22:27 ביקשתי את זה בגיטהאב ובורסל. ריפו פרטי, פריסה חיה, כותרות אבטחה פועלות, שבע בדיקות עוברות. גבול אחד שהסוכן קבע לבד: האתר בורסל מציג נתוני דמו מנוקים. הלוגים האמיתיים נשארים על השרת, נגישים רק דרך המנהרה. במילים שלו: לפרסם לוגים חיים לאינטרנט זה פחות ניטור ויותר "אוטוביוגרפיה חינמית להאקרים".

באותה ריצה הוא מצא ממצא אבטחה קריטי בהגדרות של עצמו: תוספים חיצוניים יכלו להיטען בלי רשימת אישור מפורשת. הוא כתב את הרשימה עם התוספים המאושרים בלבד והריץ את הבדיקה שוב. קריטי אחד הפך לאפס.

## שלב 9: החלקים שעדיין פתוחים

פרק היושר. למחרת בבוקר חיברתי Supabase ו־Cloudflare כדי שהדשבורד יהפוך למערכת ענן אמיתית עם התחברות. שניהם נתקעו.

Supabase החזיר 403 לפרויקט. הסיבה הייתה חוסר התאמה בין חשבונות: החיבור ב־Composio אושר על חשבון Supabase אחר מזה שמחזיק את הפרויקט. חיבור מחדש של Composio ל־Supabase מהחשבון שרואה את הפרויקט תיקן את זה בצעד אחד. המפתח הציבורי שהדבקתי לא יכול לאמת CLI בכלל, כי הוא מפתח של דפדפן, וסיסמת מסד הנתונים שהדבקתי בטלגרם קיבלה את אותו יחס כמו קודם: ההודעה נמחקה, בבקשה להחליף.

Cloudflare המשיך לדחות את פרטי הגישה עם "Invalid format for X-Auth-Key". השגיאה הזאת אומרת ש־API Token הוזן בשדה שמצפה לצמד הישן של Email ו־API Key. אלה שתי שיטות אימות שונות ו־Cloudflare לא מקבל אחת במקום השנייה. בזמן הכתיבה זה עדיין פתוח.

אף אחד מהשניים לא חוסם את הדשבורד מלהפוך לאמיתי. מה שחוסם הוא לסיים את שכבת ה־API בורסל ולבחור את כתובת האימייל האחת שמורשית להתחבר. זה הסשן הבא.
